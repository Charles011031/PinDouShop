10 个工位的计时/收费看板，给悉尼拼豆店用。

**线上**：https://charles011031.github.io/PinDouShop/  
**当前版本**：v0.2.1（2026-11-24）  
**门店**：Zetland（悉尼）

> 独立仓库 `Charles011031/PinDouShop`，main 分支根目录。

## 现在能做什么

- 10 个工位：选板型（智能板 / 普通板）开台，暂停 / 继续 / 结束。
- 两种计费：按小时（15 分钟进位、最低 30 分钟）或 2 小时套餐（超时按 15 分钟补）。
- 结算：现金 / 刷卡（手续费可设）、会员折扣；收款后本单完成。
- 系统**不设置烫位队列**：熨烫由店员线下处理，不在看板里跟踪。
- 今日营收/单数/使用中/平均客单统计；今日收款列表。
- 设置：两个板型时价、套餐价、套餐分钟、超时价、刷卡手续费、会员折扣；改完即时生效，只影响新开台。
- 多设备同步：Firebase Realtime Database 新表（与天胡门店数据隔离），3 秒轮询；断网自动用本机缓存，联网后补写。

## 数据

- 浏览器本地：`localStorage` 键 `pindou_board_v1`。
- 云端：**独立 Firebase 项目** `pindoushop` 的 Realtime Database，路径 `shops/<独立 key>/state`；和天胡项目完全分开。
- 当前是 Firebase **测试模式**（30 天后自动锁），规则是匿名读写；**网址不要发群/朋友圈**。
- 正式营业前二选一：① 收紧规则到具体路径 + 门店 PIN；② 开 Anonymous Auth，规则改成 `auth != null`（页面需加登录，我可以加）。

## 发布工具（模仿天胡）

`发布.py` 做 8 件事：

1. 版本体检：`index.html` / meta / 页面 CHANGELOG / `版本记录.md` / README 五处必须一致
2. 文件检查 + Chrome 无头冒烟（10 个工位、版本号、DOM 正常）
3. Firebase 读写检查（state、`__sysVer`、临时探针写入/删除）
4. GitHub 权限 + Pages 状态检查
5. 发布锁：同一时间只能一个发布；异常退出自动释放
6. GitHub 一次 commit 原子提交 5 个文件
7. 等线上真的返回新版本（最多 3 分钟）
8. 写 Firebase `__sysVer` 广播；打开中的页面 20 秒内自动刷新（有弹窗/计时中先弹提示条）

```bash
python3 发布.py            # 正式发布
python3 发布.py --check    # 只体检
python3 发布.py --no-tests # 跳过 Chrome 冒烟
python3 发布.py --no-broadcast  # 推送并等线上，但不广播
```

Mac 也可以双击 `发布.command`。

状态文件：`.发布状态.json`；日志：`发布日志/当前.log`；锁：`.发布锁`（都在 `.gitignore` 里）。
